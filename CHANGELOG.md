# Changelog

## [Unreleased]

### Added

- **`mut` struct fields:** a field declared `mut` (after the optional visibility, `pub mut hits: i32`) stays writable through a shared reference to the containing value, which is what lets a `&self` method keep state:

  ```riddle
  struct Counter { mut hits: i32 }

  impl Counter {
      fun bump(&self) {
          self.hits += 1;
      }
  }
  ```

  A plain field is unchanged — writing it through `&self` is still `E0309`. Being writable is a property of the field, not of the path to it, so a `mut` field is writable however it is reached: through a shared receiver, through a non-`mut` field above it, or below a `mut` field. `riddle fmt`, hover and `clue doc` all keep the modifier, and the AST accessor only counts a `mut` token written directly on the field, so `plain: &mut i32` does not make `plain` interior-mutable. Enum variant fields are the exception: they are only reachable through a pattern, and a pattern binding is a local of its own, so the modifier could never take effect — writing one reports `E0014` instead of parsing and doing nothing.

  A `&mut` to a `mut` field reached through a shared reference is confined to the call it is written in — it may be a call's receiver or argument (`self.log.push(item)`, `add_to(&mut counter.hits)`) but cannot be bound to a name or returned, because a borrow that outlived the call could alias another one. Anything else reports `E0309` with the same wording as a plain shared-reference write.

  Because a callee can still write those fields, a call rejects a borrow that points *into* one of the `mut` fields it may write: `let held = &holder.inner.value; holder.bump();` reports `E0300`, since the write can move what `held` refers to and the callee's own checks cannot see the caller's loans. What it may write comes from a per-callable interior-write summary — each function and method records the `mut` field paths it writes per parameter, truncated at the first `mut` field, and the summary follows concrete callees to a fixpoint, so a method that only forwards to another one is still tracked forwards and a method that writes `a` does not conflict with a borrow into `b`. The check covers every `&T` argument of a call, not just a method's receiver, so a free function or another type's method writing `T`'s `mut` fields through a `&T` parameter is caught too. Dynamic dispatch, function pointers, generic-bound dispatch, and bodyless `extern` declarations have nothing to summarise and fall back to assuming every `mut` field of the argument. A borrow of the enclosing value or of the field itself stays fine — `let view = &counter; counter.bump();` compiles, and the borrow observes the update. `tests/move_checker/borrow.rs`, `tests/frontend`, and `tests/mir/backend_c.rs` pin the rules; the backend test also pins the invariant that a shared reference is never emitted as `const T*`, which would make these writes undefined behaviour at `-O2`.

- **A line comment that starts its own line extends into a block comment:** inside `/* ... */`, a `//` that is the first non-whitespace text on its line comments out the rest of that line, so a terminator inside it — the `*/` in commented-out code such as `// let cached = slow(key); */` — is text rather than a close, and the block ends at the next terminator. A `//` in the middle of a line is prose: a terminator after it still closes the comment, so `/* note: // see &mut here */` stays one comment and `/* first */ // trailing` keeps its two. The scan also reaches a terminator that ends the input instead of falling out of the loop and reporting the remainder as unterminated. Pinned by `tests/frontend` and documented in the comments chapter.

### Changed

- **The default GC marks payloads by compiler-published layout instead of scanning every payload word by word.** `rgc_alloc` now takes a second argument, a flat `const uint32_t *` descriptor: `descriptor[0]` is the number of GC pointer slots and `descriptor[1 + i]` is the byte offset of slot i inside the payload. The C backend emits one `static const uint32_t riddle_desc_N[]` table per type that reaches `heap_alloc` — structs, tagged enums, tuples, nested arrays, the `{pointer, length}` headers of `str`/`&[T]`, and closure environments — and passes `NULL` for anything it cannot describe faithfully (a copied C string, or a layout listing more than 512 slots). A `NULL` descriptor keeps the previous conservative scan, so precision is per allocation and never a correctness requirement; malformed descriptors are rejected at registration and degrade to the same fallback, which keeps a codegen bug from making the collector read out of bounds. The observable effect is that an integer that merely looks like an address no longer keeps an object alive: `tests/gc` pins both directions (a typed holder reclaims its target, the same layout without a descriptor retains it) plus the malformed fallback.
- Small allocations are carved out of 64 KiB chunks into 16-byte size classes, so recycling a freed object is a free-list push/pop rather than a `malloc`/`free` round trip; payloads above 1 KiB still go straight to `malloc`, and `rgc_free` returns each block to the path it came from. `tests/gc` checks that re-allocating a freed size class reuses its chunk and that large objects bypass the classes entirely.
- **Collection statistics** are always maintained and readable through `rgc_stat_*` accessors — live bytes and objects, total allocations, collections, typed versus conservative object counts and payload scans, objects marked by the last cycle, mark and sweep duration, bytes obtained from the OS, and chunk count — plus `rgc_is_allocated` for tests. `RGC_DEBUG_STATS=1` prints the full set per collection, including mark edges by origin and what the last cycle collected. `cargo test -p gc -- --ignored --nocapture` runs a manual allocation-throughput baseline that prints the same counters.
- The heap-allocation ABI is intentionally breaking: `rgc_alloc(size_t, const uint32_t *)` replaces `rgc_alloc(size_t)`. A custom `[runtime]` provider must accept the descriptor — it may ignore it and stay conservative — and `crates/gc/README.md` plus the `clue` book section document the encoding, the allocation shape, and the statistics. A latent bug on the same path is fixed too: an `extern` C function returning `str` emitted `rgc_alloc` even in `gc = false` builds, where only `riddle_alloc` exists.
### Fixed

- **Soundness:** a shared reference no longer permits writing through it. Field assignment and index assignment implicitly dereference a reference base, so `r.n = 5` with `r: &Sample` (and `(*r).n = 5`, and `*r = value`) reached the referent without any check, and the write really did mutate the caller's value; the same hole let a `&self` method assign its own fields or call a `&mut self` method on one of them (`self.log.push(item)`), which contradicted the move checker's own E0303 contract and the book's ownership story. The new `E0309` diagnostic rejects both shapes while leaving `&mut` receivers, owned places, and raw-pointer access inside `unsafe` (the documented escape hatch) alone. Plain shared-borrow conflicts in a function body (`let a = &v; v.push(1);`) were already reported as `E0300`; the unchecked path was the reference-parameter and receiver-rooted one. Pinned by `tests/move_checker/borrow.rs`.
- A block-shaped expression in statement position no longer swallows the statement after it when that statement starts with `(`. The postfix branch of the Pratt loop ran before the `bare_block` guard that is supposed to end a statement-position block, so `if c { .. }` followed by `(*p) = 5;` parsed as `if c { .. }(*p)` — a call on the `()`-typed `if` — and the type checker rejected valid code with `E0004: cannot call value of type ()`. The guard now runs first, which leaves `*p = 5;` (already working) and every other following statement untouched. Pinned by `tests/frontend`.
- Casting a reference no longer moves it. `record_value_use` downgraded `Copy` operands to `Copy`, but the `Expr::Cast` case then re-recorded the operand as a move, so `let p = r as *const i32;` with `r: &mut i32` ended `r`'s life and any later use — `*r = 5`, or reading through `r` again — reported `E0100: use of moved value`. A cast reads the pointer out of its operand, so a reference operand is now recorded as a copy at both the cast site and in the propagation into the operand. Binding a reference (`let forwarded = r;`) still moves it. Pinned by `tests/move_checker/borrow.rs`.
- A branch that always diverges no longer contributes its moves to the join after an `if` or `match`. `if flag { return f(1); } f(2)` reported the second call as a use of a moved value, because the `then` exit was merged unconditionally even though that path never reaches the code after the `if`; the same held for an `if`/`else` where one arm diverges, and for a `match` arm such as `true => { let _ = g(1); return 0; }`. Moves are now merged only from branches that can fall through, decided by a new `always_diverges` check (a `return`/`break`/`continue` statement, a `!`-typed expression, or an `if`/`match` whose branches all diverge). A branch that does fall through still contributes, so `if flag { let _ = f(1); } let _ = f(2);` keeps reporting `E0100`. Pinned by `tests/move_checker/borrow.rs`.
- **Two fixes behind that:** a loop that reassigns a reference read out of its own place (`current = next`, where `next` came from `current.link` through a recursive type) used to make the move checker's loop-head fixpoint diverge: every round composed one more place projection, so each round produced a strictly deeper borrow, a fresh loan, and an origin set that grew by one per round — the compiler spun instead of compiling (over 300 s on a two-node list). Access places now keep at most `MAX_PLACE_PROJECTIONS` projections, and truncating keeps a prefix of the real place, which covers at least as much storage: a conflict can only be reported more often, never missed. Pinned by `tests/move_checker/basic.rs`.
- Type references are now resolved through the scope graph when MIR lowering converts a signature, a field, or a variant payload; two paths in MIR lowering (`lower_named_hir_type_for_pattern` and `convert_hir_type_with_substs`) instead scanned `item_tree.structs` and then `enums` by *name*, across packages. A local `enum Chain { End, Link(&Chain) }` therefore took std's `struct Chain` for its own payload and silently read the wrong layout at run time (renaming the type hid it). Pinned by `tests/interpreter` (`recursive_type_may_share_a_name_with_a_std_type`). A type whose name matches a std type no longer breaks std's own sources either: impl scopes were keyed by struct *name*, so std's `impl<I, J, T> Iterator for Chain<I, J, T>` was attached to a user's same-named `struct Chain`, and std then reported a bogus `E0032` (attributed to the user's file). The scope is now chosen by name *and* package, which leaves single matches untouched. Pinned by `tests/interpreter` (`a_type_may_share_a_name_with_a_std_type`).
- **Recursive types compile.** A struct or enum that reaches itself through a reference — `struct Node { next: Option<&Node> }`, `enum List { Nil, Cons(i32, &List) }` — used to overflow the compiler's stack while lowering. The MIR type of a struct expanded every field eagerly, so `Node` unfolded into `Option<&Node>` into `Node` and never ended; the type checker's own `E0072` rule already accepts indirection, and `tests/type_checker/structs.rs` has accepted `struct Node { next: &Node }` since long before it could be compiled. A nominal struct is now one definition shared behind an `Arc` with the occurrence inside its own fields a `Weak` back-reference to it, so the type graph closes a cycle instead of expanding forever, and the module owns the definitions for as long as its types are resolved. Field lists are read through that handle everywhere they are needed (interpreter layouts, C struct emission, drop glue, rendering), and the C backend's struct-depth ordering and function-pointer collection now visit each definition once, which is what keeps their walks finite. `Node` values can be built, traversed recursively, promoted to the GC heap and read back through two `next` hops. Pinned by `tests/mir/lower.rs` (the definition stays shared and the back edge resolves to it), `tests/mir/std_behavior.rs` (the C backend, with and without GC) and `tests/interpreter` (five end-to-end traversals).
- **`riddle-lsp` no longer renders an unanalysable file as clean.** When a content change could not be mapped onto the buffered text — a column inside a surrogate pair, a column past the end of a line, a line the document does not have — the server used to drop the document from its state and answer nothing. An omitted document is indistinguishable from a file with no problems, so the editor cleared its markers and the pull path returned an empty report; a document in that state now keeps its buffer, is excluded from analysis (so it cannot corrupt the diagnostics of the files that share its project), and publishes a single `LSP0001` error asking for the file to be reopened. Positions are also clamped rather than rejected wherever clamping is meaningful, and a range-less full-text change recovers the document automatically. Pinned by `tests/riddle_lsp/editing.rs` and the `LSP0001` case in `editors/lsp-smoke.mjs`.
- **Position encoding is negotiated instead of assumed.** The server answered `positionEncoding: utf-16` unconditionally and never read the client's `general.positionEncodings`, so a client that speaks only UTF-8 or UTF-32 received columns that drifted on every line with a multi-byte character. The encoding is now chosen from the client's list (UTF-16 preferred, since it is the protocol default), every offset the server sends or receives uses it, and a client that offers none of the three is rejected with an explanatory error rather than served the wrong coordinates. Positions are computed through a per-document column table, which also removes the O(line length) scan per mapped symbol and diagnostic.
- **Code actions: `source.fixAll` and `source.addMissingImports`, and the kinds are announced.** `source.organizeImports` was implemented but invisible, because `codeActionProvider` was advertised without `codeActionKinds` — VS Code's "Source Action…" menu could not list an action it had not been told about. The provider now declares `quickfix`, `source.organizeImports`, `source.addMissingImports` and `source.fixAll`; the two new kinds reuse the existing analysis-backed fixes, and a request for `source.fixAll` computes that analysis once instead of once per kind.
- **`textDocument/rangeFormatting`, `workspace/diagnostic`, `semanticTokens/range`, and `willRenameFiles`.** Range formatting reformats the document and keeps only the line-level edits intersecting the range, so a partial format cannot touch text outside the selection. Workspace diagnostics were already computed for unopened modules and local dependencies — only the request was missing, so `workspace_diagnostics` is now advertised and served from that engine. Semantic tokens can be requested for the visible window alone. The server announces a `willRename` file-operation filter for `**/*.rid`, and `Clue.lock` joins `Clue.toml` in the watched set, so a lockfile rewrite invalidates the project.
- **The document outline contains `impl` blocks, and item ranges are honest.** `TopLevelItem::Impl` was mapped to `None`, so every method defined in an `impl` block was missing from the file's outline and breadcrumbs even though `workspace/symbol` found it. The outline now carries one container per `impl` — named for the implementing type, with the trait as `detail` and the methods, consts and associated types as children — and `range` covers the whole declaration while `selectionRange` covers the identifier. The same split is applied to call-hierarchy and type-hierarchy items and to the project index, whose symbol lookup is now a hash map instead of a linear scan per hierarchy edge.
- **Semantic tokens cover doc comments, block comments, and multi-line tokens.** Only `SyntaxKind::LineComment` was classified, so `///`, `/** */` and `/* */` regions had no highlighting at all, and any token spanning several lines was dropped outright. Every comment flavour is classified now and a multi-line token is emitted once per line. Folding likewise became three-kinded: braces are regions, runs of comment lines are comments, and a run of `use` declarations is an import group.
- **`Clue.toml` completes the schema of nested tables.** `[dependencies.<name>]` and `[[bin]]`/`[[example]]`/`[[test]]`/`[[bench]]` returned no completions at all, because any section other than the five top-level ones was treated as "user-chosen names, no noise". The names are user-chosen; the keys are not, and the schema for them already existed for diagnostics. Nested section headers are also recognised now, so `[dependencies.foo]` matches instead of falling through.
- **Inlay hints are syntax-driven and padded.** Argument hints paired parameter names with the first token of each argument, which misaligned as soon as an argument was more than one token (`f(a + b, c)`), and every hint left `paddingLeft`/`paddingRight` unset while its label already carried the separator. Argument boundaries are now found by bracket depth and the hints declare their padding.
- **`editors/` routes `Clue.toml` to the server.** The manifest is registered as its own language id in the VS Code extension (with a TOML language configuration), matched by filename in the Helix configuration, and the extension gained `riddle.inlayHints.enabled` and `riddle.trace.server`. Zed and IntelliJ still scope the server to `.rid`; `zed_extension_api 0.1.0` has no way to declare a second language for one server, and IntelliJ's LSP integration needs the TOML plugin. The server also accepts a `--trace-latency` flag that prints per-phase timings to stderr.
- **Latency and protocol behaviour are covered by tests.** The protocol-level smoke test now asserts the full capability set, the `impl` outline entry, the range/selection-range split, the `LSP0001` desync path, a refused rename, and nested manifest completions — and it runs in the pull-request workflow instead of only on a schedule, which is why capability regressions used to reach the client unnoticed. `tests/riddle_lsp/editing.rs` covers clamping, rejection atomicity, and the clamped offset mapping.

### Changed

- **`riddle-lsp` analyses less and blocks less.** A content change used to schedule two whole-project passes at once — diagnostics at `Check` depth and a workspace-index rebuild at `Infer` depth — both on the same project session, so typing paid for two compilations per keystroke. Indexing now happens on save and on file events rather than on every keystroke (`textDocumentSync` advertises save support for this), and the server sends one analysis per change. `formatting`, `folding_range`, `selection_range` and `document_link` moved off the async executor: tower-lsp polls its handlers inside a single driver task, so a synchronous reformat stalled every other request in flight. Pull diagnostics are cancellable rather than hard-coded non-cancellable, and a superseded or failed pull answers "unchanged" instead of an empty report.
- **`riddle-lsp` coalesces completion requests by default.** `--completion-delay-ms` defaulted to `0`, which skipped the debounce entirely, so every keystroke in a project started its own whole-project completion. The default is now 40 ms.
- **Completion no longer recompiles the project twice per keystroke.** A member completion analyses the source once with a marker at the cursor and once more with the terminator repaired, and the repaired variant is what yields the items. `ProjectSession` cached a single analysis keyed by an input revision that every overlay change bumped, so the two analyses never shared work and the second paid a full recompile — measured at 85 ms against 15 ms for the first. Analyses are now also remembered by a fingerprint of the inputs they were produced from: the caller's overlays plus the file stamps the session already checked, so a disk-only edit invalidates the entry and an alternating input pattern hits. Measured on a 1/8/24-module project (release build, `cargo bench --bench lsp_completion`): a completion arriving after a one-character edit went from 97 / 113 / 155 ms to **4.2 / 8.8 / 19.9 ms**, and a steady-state request in the stdio smoke test from 848 ms behind an in-flight diagnostics pass to 167 ms.
- **`cargo bench --bench lsp_completion` measures editor latency.** It builds a real Clue project on disk and reports the cold request, a warm request, a request after a one-character edit, the `Check`-depth diagnostics pass, and the `Infer`-depth index pass — the figures the language server's `--trace-latency` phases are meant to explain. The benchmark is what showed that the *second* analysis, not the first, dominated a keystroke.
- **Completion no longer deadlocks on a barely-typed buffer.** Reported from Zed and VS Code: after typing `unreachable!("Fuckypi");` and starting the next statement, the language server stopped answering — `textDocument/completion` never returned, and every later request (hover, symbols) hung too. The completion path analyses the marked source, and when the marker is not resolved as a scope reference — the normal case for a buffer like `f` — it re-analyses the unmodified source as a fallback. Both passes locked the same `AnalysisSessions`, and the fallback locked a session whose guard was still held by the primary pass, so it waited on itself forever. The fallback now drops the guard first and re-takes it; `fallback_sessions` was removed entirely, because it always aliased `sessions` and the separate set it once provided is unnecessary now that analyses are cached by input fingerprint. A standalone buffer went from never answering to 148 ms / 7 items, `fun main() {` from never to 84 ms / 66 items.
- **A type reference is no longer identified by where it was written.** `HirTypeRef` and `HirAssocTypeConstraint` derived `Hash` and `PartialEq` while carrying a `TextRange` — `trait_range` on the `impl Trait` / `dyn Trait` variants, `range` on associated-type constraints — so a type's identity moved with the source around it. The pipeline bundles the user's code *before* the standard library (`format!("{source}\n\n{std}")`), so editing one character byte-shifted every standard-library `impl Trait`; the incremental checker hashes signatures into its type-context fingerprint, so all ~827 cached standard-library bodies were discarded and re-type-checked on every keystroke, at ~688 ms each. Twenty higher-order functions (`or_insert_with`, `fold`, `map`, `and_then`, …) take `fun` parameters and were the ones changing. Both types now implement `PartialEq`/`Hash` by meaning rather than position, matching what `HirPath` already did. A phase trace of one keystroke went from `[checked 827, reused 0]` to `[checked 1, reused 826]` (~17 ms), with globals reused; `tests/clue/project_session.rs` asserts exactly that, and `tests/type_checker/incremental.rs` pins that an edit outside declarations cannot move the type context.
- **The language server keeps one set of analysis sessions, not two.** `completion_sessions` and `analysis_sessions` each built the standard library's ~827 checked bodies from scratch, so whichever one was asked built it again; they are now one `sessions` field. Both the marker variant and the unmarked source are cached by input fingerprint, so the isolation the second set existed for is no longer needed.
- **`IncrementalParser::set_source` reuses the parse when the text is unchanged.** It called `parse_full` unconditionally, and the language server hands it the same ~240 KB bundle (user code plus the whole standard library) on every check, so each request reparsed all of it — the dominant cost of a keystroke, and enough to invalidate the green trees the type checker's body fingerprints are keyed on. `tests/scope_graph/incremental.rs` pins both halves: identical text reuses the tree, changed text does not.
- **The type-context fingerprint no longer depends on source positions.** `type_context_fingerprint_with_ranges` also hashed `format!("{tree:?}")`, and `Debug` carries every item's `TextRange` — so editing one character moved the items after it and invalidated every cached body in the bundle, including the standard library's. It now hashes `type_context_fingerprint` alone: declarations still participate through the per-item hash functions, and bodies are tracked individually by `body_fingerprint` / `syntax_body_fingerprint`. `context_fingerprint_parts` splits it into declarations, structure and signatures so a trace can say which part moved.
- **Compiler phase timing, and the incremental checker reports why it missed.** `RIDDLEC_PHASE_TIMING` makes the pipeline print parse / lower / scope-graph / type-check / escape / move-borrow durations, the type-check line carries `[checked N, reused M]` plus a breakdown of why cached bodies were not reused (`absent`, `missed_context`, `missed_body`, `missed_replay`, `globals_rebuilt`), and each standalone check reports its checker's identity, its body count, and — as the body loop starts — the cached entry count against the cached and current context fingerprints. Session creation and reuse are traced under the same variable, including which session set a request landed on. Off by default; one `Instant` read per phase boundary when on. This instrumentation is what found the position-dependent type identity above: of 36 whole-project checks in the stdio smoke test, 21 were a checker's first fill and only 1 was a warm cache that still re-checked everything. `context_fingerprint_parts` splits the fingerprint into declarations, structure and signatures so a trace can name which part moved.

### Fixed

- `textDocument/rename` returned `null` for a target it would not rewrite, which clients render as a rename that silently does nothing. `prepareRename` and `rename` also disagreed about which targets are renamable, so a target the first accepted could be refused by the second. Both now share one resolver and a refusal is reported as `invalid_params` with the reason.
- An analysis cache keyed only on the caller's overlays is not enough for a project whose modules are read from disk: editing a module that is not open in the editor changes no overlay, so the fingerprint has to cover the file stamps the session checks. Caught by `tests/riddle_lsp/workspace_and_cli.rs` (`workspace_sessions_observe_project_disk_edits`), which edits a closed module and demands the new diagnostic.

## [0.3.0] - 2026-09-19

### Added

- **Or-patterns in match arms:** `match x { A | B | C => … }` accepts a disjunction of alternatives at the top level of a match arm, like Rust, including the optional leading `|` (`match c { | Color::Red | Color::Green => 1, … }`) which is consumed before the pattern so a single alternative still lowers as a plain pattern. Each alternative is checked and lowered independently (coverage expands to one matrix row per alternative via `lower_matrix_rows`, and MIR folds the per-alternative guard conditions together with `BitOr`), and the type checker reports `E0010` — with a hint to bind in the arm body or split the arm — when an alternative binds a variable, since every arm body must see the same bindings. `A | B` is a match-arm form only: `let 1 | 2 = x` now reports that instead of silently discarding `| 2 = x` on the recovery path, and `if let A | B = v` fails to parse. Nested alternatives (`Some(1 | 2)`) are rejected by the parser; the coverage checker maps any `Or` outside an arm's top level to `MatrixPat::Invalid` rather than under-approximating it with the first alternative. Pinned by parser (`OrPattern` syntax kind), type-checker, interpreter, and C-backend tests.
- **Collection iteration and `TreeMap` views:** `HashSet` and `TreeSet` are now iterable — `iter()` plus `IntoIterator for &Set` — yielding `&T` in insertion order (`Hash*`) or sorted order (`Tree*`). `TreeMap` gains `keys()` / `values()` view iterators and `range(&start, &end)` (start-inclusive, end-exclusive, in-order) alongside the existing entry iteration; all three views implement both `Iterator` and `IntoIterator`. `tests/interpreter` and `tests/mir/std_behavior` pin the ordering on both backends. The hash collections' order is insertion order only while nothing has been removed — `remove` back-fills the vacated slot with the last bucket (swap-remove), which the method docs now state.
- **Interpreter benchmarks:** `cargo bench` now runs `benches/interpreter.rs` (criterion), timing `main` of three fixed workloads — tight arithmetic loops, recursive `fib`, and `Vector` churn — through a fresh interpreter session per iteration with checksummed results, guarding the executor's hot path against regressions.
- **Deterministic parser fuzzing and direct ast/hir tests:** `tests/frontend/fuzz.rs` drives seeded rounds of token soup, corpus mutation, and unicode noise through the parser (the green tree must round-trip every input byte); the token alphabet includes newlines, CR, tabs and every comment glyph, and the corpus carries multi-line commented programs, so the `//`-comment reparse bailout is fuzzed too. Incremental rounds apply `try_apply_edit` sequences whose offsets are floored to character boundaries and whose payloads may be multi-byte, and each must stay tree-identical to a full reparse; an edit that splits a code point must be rejected without mutating parser state. All seeds are reproducible on stable Rust. `tests/ast_hir` exercises the typed AST accessors (signatures, let-else, string literals, use trees, attributes/doc comments), HIR body lowering shape, local name resolution, and the `Place` prefix algebra directly, without the type/move checkers layered on top.
- **MIR interpreter and `riddle run` / `riddle repl`:** a tree-walking interpreter (`crates/interpreter`) executes fully lowered MIR modules with C-backend-compatible semantics — wrapping integer arithmetic, trapping division (`division by zero` / `integer division overflow`), masked shifts, saturating float→int casts, bounds-checked indexing, rustc-style panic rendering, and pointer-identity comparisons. Externs declared by the bundled standard library are served by native shims (`std::fs`, time, random, process I/O, and the `rgc_*` allocation facade), so programs run without a C toolchain. `riddle run file.rid [-- args] [--seed N]` executes a single file (exit codes mirror compiled aborts; `--seed 0` seeds from the clock, missing `main` reports `E0401`, buffered output is flushed ahead of each stdin read, and panics render real file locations — mapped back through standard-macro expansion and into the bundled std region), and `riddle repl` starts a rustyline-backed session: definitions accumulate at the top level, `let`/expression lines journal inside a generated `main` and re-run per evaluation (side effects replay; `:reset` clears), expressions echo their `{:?}` value and bind `__`, and `:mir` dumps the last compiled module. `riddlec --emit mir` pretty-prints the MIR of a program. A new `tests/interpreter` suite (43 tests) mirrors the `std_behavior` scenarios with no C compiler required.
- **`clue doc`:** generates static HTML API documentation from the HIR item tree and doc comments (`///`, `/** */`, trailing `//<`), one page per module with a sidebar, signatures, and markdown-lite prose (headings, lists, code fences); impl and trait blocks list their methods with their own doc comments. By default only `pub` items; `--document-private-items` includes the rest, `--open` opens the result, and `--no-std` documents the standard library itself (`std/` now carries a `Clue.toml` and `cd std && clue doc --no-std` produces the full std reference). Signature rendering moved from the LSP into `hir::render` so hovers and docs share one implementation; `Clue.toml` gains optional `description`, `authors`, and `repository` fields, surfaced in `clue metadata`.
- **Global build cache:** library builds publish their artifacts (`.c`, object, `.rlib`, `.rmeta`, staticlib/cdylib) into `$CLUE_HOME/cache/build/<triple>/<profile>/<fingerprint>/` and later builds with an identical fingerprint restore from there (`clue: cached library`), so vendored copies and registry dependencies of the same content compile once per machine. The cache is disabled with `[build] cache = false` or `CLUE_BUILD_CACHE=0`; `clue clean` only touches project state. Binary freshness now also verifies every dependency archive still exists instead of trusting the executable alone.
- **Parallel dependency builds:** sibling dependencies of one package build across `-j` workers (default `available_parallelism`), replacing the strictly sequential recursion; package cycles are still caught per worker and same-package concurrency still serializes on `.build-lock`. Artifacts are collected in manifest order, so link arguments stay deterministic regardless of worker finish order.
- **Reference comparisons:** `std::cmp` gained the blanket reference impls — `impl<T: PartialEq> PartialEq for &T` plus `Eq` / `PartialOrd` / `Ord` variants, comparing pointees — so `&a == &b`, `&a < &b`, and `T: PartialEq` bounds over references now check (previously `E0036`) and dispatch on both backends. `Ordering` also implements `Debug`, rendering `Less` / `Equal` / `Greater` by name like the derived impls `Option` / `Result` already carry.

### Changed

- **Performance:** the interpreter's execution loop no longer clones every basic block's instruction vector and terminator on each pass. Functions are shared behind `Rc` handles, so an activation borrows its instruction stream while `eval_inst` still takes `&mut self` for memory — about 22% faster on a `Vector`-churn workload (1.57s vs 2.01s per run) and now pinned by the criterion benchmarks above. The rewrite also folded `UnOp` into `eval_inst`, which changed which register `Ref`/`MutRef` resolves a home from: the operand's rather than the instruction's destination. No program in the suite distinguishes the two, so it is disclosed here rather than described as a fix.
- **Performance:** `Vector::sort` is a stable bottom-up merge sort — O(n log n) element moves with a one-time scratch buffer — replacing the O(n²) insertion sort; the left run parks in the scratch buffer while the right run merges in place, and ties keep insertion order (pinned by stability tests on both backends). A trailing run with no right partner is already in place, so the merge loop breaks there instead of spinning through `merge_runs(start, len, len)` for every remaining `start`.
- **Breaking:** bitwise operator precedence now follows Rust/C: shifts bind tighter than `&`, then `^`, then `|`.
- **Breaking:** integer parsing returns `Result<T, ParseIntError>` with `Empty`, `InvalidDigit`, `PosOverflow`, and `NegOverflow` error kinds instead of `Option<T>`.
- **Breaking:** `HashMap` gains the Rust-style entry API: `entry(key)` returns an `Entry` enum (`Occupied { value: &mut V }` / `Vacant { key, map: &mut HashMap }`) with `or_insert`, `or_insert_with` (an `impl FnOnce() -> V` default factory), and `or_default`; the interim `entry_or_insert` / `entry_or_insert_with` / `entry_or_default` convenience methods are removed (`get_or_insert` stays).

### Removed

- **Breaking:** the `fun(params) { body }` anonymous-function syntax has been removed in favor of bracket lambdas. `fun(x) { x + 1 }` becomes `[x -> x + 1]`, and `move fun(x) { ... }` becomes `move [x -> ...]`; both now produce a dedicated parse diagnostic pointing at the bracket-lambda replacement. Bracket lambdas already cover parameter type annotations (`[x: i32 -> x]`), destructuring patterns (`[(left, _) -> left]`), zero-parameter forms (`[ -> body]`), block bodies (`[v -> { ... }]`), and postfix method-call sugar (`values.map [v -> v * 2]`). Capabilities that were `fun`-lambda-only are gone rather than migrated: generic lambda parameters and bounds, `where` clauses, return-type annotations, and self-recursive bindings — express these with named (generic) functions, which monomorphize per call site and may recurse. The syntax kind, AST node, and HIR lowering for the removed form were deleted; `syn`'s proc-macro expression classifier now recognizes bracket lambdas as `Expr::Closure` (params before the top-level `->`, body after it, including destructuring patterns) instead of `fun`-token closures.

### Changed

- **The default GC marks payloads by compiler-published layout instead of scanning every payload word by word.** `rgc_alloc` now takes a second argument, a flat `const uint32_t *` descriptor: `descriptor[0]` is the number of GC pointer slots and `descriptor[1 + i]` is the byte offset of slot i inside the payload. The C backend emits one `static const uint32_t riddle_desc_N[]` table per type that reaches `heap_alloc` — structs, tagged enums, tuples, nested arrays, the `{pointer, length}` headers of `str`/`&[T]`, and closure environments — and passes `NULL` for anything it cannot describe faithfully (a copied C string, or a layout listing more than 512 slots). A `NULL` descriptor keeps the previous conservative scan, so precision is per allocation and never a correctness requirement; malformed descriptors are rejected at registration and degrade to the same fallback, which keeps a codegen bug from making the collector read out of bounds. The observable effect is that an integer that merely looks like an address no longer keeps an object alive: `tests/gc` pins both directions (a typed holder reclaims its target, the same layout without a descriptor retains it) plus the malformed fallback.
- Small allocations are carved out of 64 KiB chunks into 16-byte size classes, so recycling a freed object is a free-list push/pop rather than a `malloc`/`free` round trip; payloads above 1 KiB still go straight to `malloc`, and `rgc_free` returns each block to the path it came from. `tests/gc` checks that re-allocating a freed size class reuses its chunk and that large objects bypass the classes entirely.
- **Collection statistics** are always maintained and readable through `rgc_stat_*` accessors — live bytes and objects, total allocations, collections, typed versus conservative object counts and payload scans, objects marked by the last cycle, mark and sweep duration, bytes obtained from the OS, and chunk count — plus `rgc_is_allocated` for tests. `RGC_DEBUG_STATS=1` prints the full set per collection, including mark edges by origin and what the last cycle collected. `cargo test -p gc -- --ignored --nocapture` runs a manual allocation-throughput baseline that prints the same counters.
- The heap-allocation ABI is intentionally breaking: `rgc_alloc(size_t, const uint32_t *)` replaces `rgc_alloc(size_t)`. A custom `[runtime]` provider must accept the descriptor — it may ignore it and stay conservative — and `crates/gc/README.md` plus the `clue` book section document the encoding, the allocation shape, and the statistics. A latent bug on the same path is fixed too: an `extern` C function returning `str` emitted `rgc_alloc` even in `gc = false` builds, where only `riddle_alloc` exists.
### Fixed

- **Structured associated-type bindings in generic bounds now unify with the impl's type.** A bound whose associated-type value is a pattern over the callee's generics — `I: Iterator<Item = &T>`, `S: Source<Out = (T, i32)>`, `Out = Vector<T>` — was rejected with `E0035` ("type `X` does not satisfy bound `Trait`") even though the impl existed. `collect_bound_assoc_subst` bound the *whole* associated type to every parameter the pattern mentioned, so `Out = &T` against `type Out = &i32` bound `T = &i32` (lowering the bound to `&&i32`) and the constraint check could not unify it; the call site then also reported the misleading `E0308`/`E0036` follow-ons. Each parameter is now matched against the associated type at its own position through `collect_subst`, seeded inference variables are cleared first, and the bindings are committed only when the pattern matches structurally — `T = i32` is inferred, and a genuine mismatch still reports `E0035`. Pinned by `accepts_structured_associated_type_bindings`, which covers reference, tuple, and generic-`for` binding shapes (`IntoIterator<Item = &T, IntoIter = J>`).
- **`T: Copy` bounds are honored by the move checker.** Moving out of a shared reference behind a copyable parameter (`fun dup<T: Copy>(value: &T) -> T { *value }`) reported `E0308`, and reusing such a value (`let first = value; let second = value;`) reported `E0100`, because the move checker consulted only the global trait environment, which holds no impl for a bare parameter. The type checker now records each body's lowered bounds (including the enclosing impl's) in `TypeCheckResult::body_bounds`, and the move checker decides `Copy` against those assumptions. This also closes the generic associated-type payload boundary recorded in 0.3.0: `match it.next() { Some(x) => *x }` in a generic body now compiles and runs on both the C backend and the MIR interpreter. Parameters without a `Copy` bound still report `E0308`, and a non-`Copy` type passed where a copyable parameter is required still reports `E0035`; pinned by `generic_copy_bound_allows_deref_move_and_reuse` and `unbound_parameter_still_cannot_move_out_of_reference`.
- **Generic-bound `Iterator` dispatch and the raw-pointer iterator gap.** Three follow-on layers complete the manual-`next` story. (1) `Vector::get`/`get_mut` reach their elements through the slice accessors (`as_slice().get(i)`) instead of a `*mut T` detour after their bounds check — identical semantics, but the provenance stays trackable, so the tree/hash collection iterators (which read nodes through `Vector::get`) stop being conservative; borrowing an empty array literal (`&[]` in `as_slice`'s empty branch) no longer poisons the merged summary opaque, and `(ptr, len) as &[T]` casts keep their origins while dropping the pair's slot structure that a later index step would wrongly "iterate". (2) Generic-bound calls (`fn f<I: Iterator>` calling `it.next()`) use the join of every impl's summary, and a trait method declared `#[flow = "behind_reference"]` — `Iterator::next`/`next_back` carry it — additionally licenses adapters' summaries to thread the inner call's provenance (a value-shaped callee such as `self.f(value)` can only return references derived from its captures and arguments, so that merge no longer goes opaque). The contract is verified after the fixpoint against every impl by walking each origin's field path against the impl's self type — any step past a reference or `*mut T` prefix marks the region outside the receiver — and one failing impl demotes the whole trait method back to the conservative merge; loans mapped from behind-reference origins never conflict with borrows of the receiver's own storage. (3) Monomorphized instances now seed the impl's associated type aliases (`type Item = &T`) into the substitution — `next`'s `Option<Self::Item>` previously lowered with a Unit payload — and call sites take the instance's own return type when the generic body's recorded type is a placeholder. Known boundary: the checker still records associated-type returns in generic bodies as placeholder types, so a generic function that pattern-matches the payload (`match it.next() { Some(x) => *x }`) passes borrow checking but cannot yet be code-generated; payload-discarding generic consumption works end to end.
- **Manual `Iterator::next` calls work on reference-yielding iterators.** `let a = it.next(); let b = it.next();` on an `Item = &T` iterator reported `E0302`: the move checker's fallback tied the elided return reference to every reference input — most importantly the fresh `&mut it` receiver loan — so the first element kept the iterator mutably borrowed. The reference-flow summaries now carry field/index paths (`&self.values[i]` records "param 0's `values` field" instead of flattening to the whole parameter; struct literals keep per-field flow so a returned iterator's reference fields stay projectable), a concrete-impl call resolves its summary instead of the trait-signature fallback, and instantiation routes a path-carrying origin through the receiver's *stored* field loans — the `&[T]` inside the iterator — so the element reference carries that loan, the receiver loan expires at each call, and consecutive `next` calls are fine while mutating the underlying data under a live element is still rejected. Receivers with no projectable stored origins (an owned `&self.value` borrow), summaries that go opaque through raw pointers (`Vector::get`'s `*mut T` detour — kept exempt per the `unsafe` escape hatch, which is why the tree iterators stay conservative), and generic-bound dispatch (`I: Iterator`) keep the historical whole-receiver mapping. Two of its knock-on fixes: `[T]::get`/`get_mut` index directly after their bounds check instead of detouring through `as_ptr()` (identical semantics, trackable provenance), and **a binding that is never used after its pattern no longer holds its loans forever** — its borrow now dies at its binding site (NLL-style), which previously kept e.g. an unused `let r = &p;` blocking `let q = p;` forever; two `move_checker` tests that pinned the old conservative behavior were updated to use their bindings.
- Calls into an impl whose self type is itself a reference now pass arguments at the right reference level. `lower_receiver_arg` / `lower_comparison_arg` treated "expected parameter is ref-shaped and operand is ref-shaped" as pass-through, so once `impl PartialEq for &T` existed, `a == b` on `&i32` operands fed `&i32` values into `&&i32` parameters (and the default-method bodies `ne` / `lt` re-dispatched with the same skew) — the callee loaded a pointer out of the pointee. A new pure lookup, `mono_method_param_type`, computes the substituted parameter type of the exact instance a call selects (binding `Self` and trait generics like `Rhs` the way the instance's body is typed), and the argument paths materialize the missing level only when the substituted parameter is reference-of-reference and the operand carries exactly the inner reference — every other call keeps byte-identical lowering, which matters because these paths run for every method call in std. The impl bodies delegate through one deref + bound method call (`(**self).eq(&**other)`), which cannot re-select the blanket impl at monomorphization time. Pinned by interpreter and C tests covering `==` / `!=` / ordering operators, method syntax, `cmp` on references, and generic `T: PartialEq` functions.
- Private free functions that collide by name no longer emit duplicate C symbols. MIR symbols are package-qualified only, so every std free function is bare-named and a single-file build's user functions are too: `fun mix64` in user code next to std's `hash::mix64` produced two `riddle_f_6d69783634` definitions and gcc died with `static declaration follows non-static declaration` — while in the interpreter the name-keyed dispatch table silently let std's copy shadow the user's. `qualify_symbol` now counts final free-function symbols and renames each colliding party to `fun::<fid>::<name>` (mirroring `method_symbol_base`'s existing `method::<fid>::` fallback); extern and `c_export` names are ABI and never participate, and `main` keeps its exemption. Same-named privates in different modules of one package get the same treatment. Pinned by a C test compiling a user `mix64` alongside `HashMap`.
- **Soundness:** writing through a reference is now borrow-checked against the referent. `m.value = 2` (and `*m = v`) with `m: &mut bag` resolved its check place at the reference binding, so a derived shared loan on the referent — `let r = &m.value;` held alive by a closure capture, or plainly still live — never overlapped and nothing fired, contradicting the book's own E0303 contract (`bag.set(2)` through `&mut self` was already rejected). The assignment path now derives write targets from the reference root's current origins (`local_origins` / `param_origins`, projected by the written field/index chain — assignments never read their LHS, so the path expression carries no recorded origins), and reports `E0300` when a derived loan is still alive; the reference's own loan family, including a reference parameter's seed loan, stays excluded exactly like the method-call path, and writes after the derived reference's last use remain allowed. std is structurally immune (it holds no local reference aliases), and `tests/move_checker` pins the plain, closure-held, after-last-use, and whole-`*m` shapes.
- Generic trait methods now dispatch on tuple receivers. `Vector<(i32, i32)>::sort` called `.lt` through the `PartialOrd` function slot with nothing filled in — the interpreter trapped with `call_indirect on a non-function value` while `<` on the same pair worked — because monomorphization never unified tuple `Self` types and std shipped no tuple trait impls. `std::cmp` / `std::hash` / `std::fmt` gained `PartialEq`/`Eq`/`PartialOrd`/`Ord`/`Hash`/`Display`/`Debug` impls for tuple arities 2..=6 (lexicographic order, comparing element-wise through each element's own impl), and the monomorphizer resolves a concrete tuple receiver against a tuple impl self-type by structural substitution (`tuple_impl_subst`), so static slots fill correctly on both backends. Nested tuples (`Vector<((i32, i32), i32)>`) recurse through the same path; interpreter and C tests pin sorts, `HashMap`/`TreeMap` keys, and direct `.lt`/`.cmp` calls on tuples instead of the custom-struct workarounds the old tests used.
- `std::cmp::Ordering` now implements `PartialEq` / `Eq` / `PartialOrd` / `Ord`, comparing variants by declaration order like Rust's derived impls. It carried only `Copy`, so `x.cmp(&y) == Ordering::Equal` — the ordinary way to test a comparison result — failed with `E0036` and `Vector<Ordering>::sort` had no method to dispatch through; interpreter and C tests pin equality, `!=`, ordering between variants, and a sort.
- **Soundness:** borrows captured into a lambda now live as long as the lambda value itself. A captured `Option<&T>` (by value or by shared reference) previously let its loan on the container expire at the lambda's closing bracket, so `let r = v.get(0); let f = [ -> { use r } ]; v.push(2); f();` compiled and read through a dangling pointer into the reallocated buffer — the container-interior-borrow hole this project's own book admitted at `collections.md`. The move checker attaches the captured place's outstanding loans to the lambda expression, so they expire at the lambda's last use (the call), and `E0300`/`E0303` fire for structural modifications in between; modification after the closure's last call is still allowed. Raw-pointer escapes (`as_ptr`) remain the `unsafe` escape hatch.
- The incremental parser no longer panics when an edit changes a node's grammar shape. Editing inside a `for` header can glue `for` into the inserted text (`for i in 0..10` → `forreturn{ }`), so the fragment reparses as a `StructExpr` where the tree held a `ForExpr`, and `SyntaxNode::replace_with` hit rowan's kind assertion — a hard panic reachable from LSP typing. A kind mismatch now skips that node and lets a wider ancestor, or a full reparse, produce the canonical tree. Pinned by a minimized regression test that rowan-asserts when the guard is removed, and by the fuzz equivalence property over a multi-line, comment-bearing corpus.
- The interpreter evaluates the eager bitwise operators on `bool` operands. `match` lowering folds pattern tests and arm guards together with `BitAnd` / `BitOr` (and or-pattern alternatives with `BitOr`), so iterating the hash collections in `riddle run` previously aborted with `binary op BitAnd on unsupported type Bool` because no std code path had ever reached that shape under the interpreter. `&&` / `||` are unaffected: they lower to short-circuit control flow with a phi, not to bitwise operators, and tests on both backends pin that the right-hand side of `&&` stays unevaluated while `&` evaluates it.
- Indexing through a reference to a fixed-size array no longer strides by the whole array. `let view = &values;` on `[i32; 3]` gave a `&[I32; 3]` base whose element size the interpreter took as `size_of([I32; 3])`, so the second element sat two arrays away and the first read past the allocation died with `interpreter internal error: … escapes allocation` instead of returning a value. Interpreter and C tests walk an array reference, a `&pair.a` field, and the out-of-bounds abort.
- An unterminated block comment is now an error. The lexer runs `/*` to end of input when no `*/` arrives, so a stray opener silently deleted every item after it and the program still compiled: `riddlec` reported `no main function found` for a file that plainly defined `main` further down, and a file whose `main` came first compiled and ran as if the remainder did not exist. `riddlec`, `clue check` and `clue run` now report `unterminated block comment` at the comment. `riddle run` and `riddle repl` initially kept executing the truncated program: the macro-expansion pipeline builds its green tree from a token stream through `parse_tokens`, which never ran the lexer diagnostics, so that path now reports the same error.
- **Soundness:** the move checker now tracks parameter-rooted places. Field moves out of by-value parameters (`let r = o.res` where `o: Owner`), `match`/`if let`/`while let` scrutinees that are parameters, and move closures capturing parameter fields were previously invisible: no `E0100`/`E0305`/`E0304` diagnostics fired and MIR dropped each moved field twice. `hir::Place` roots are now a `PlaceRoot` enum (pattern binding / parameter / lambda parameter), so partial moves, borrow conflicts, guard restrictions, and drop-flag clearing all apply to parameters. Reference parameters keep their previous leniency for raw-pointer access inside `unsafe` blocks, and runtime-index moves on parameters are still resolved at runtime through per-element drop flags.
- **Soundness:** a reference stored into a binding that outlives its block now promotes the referent. `let r: &i32; { let x = 5; r = &x; }` kept `x` on the stack, producing a dangling reference that only survived because the C backend flattened block scoping. Escape analysis now promotes block locals whose provenance reaches an out-of-block binding or the block tail value.
- **Soundness:** `FnSummary.escaping` now includes reference parameters whose place escapes (captured into an escaping lambda, forwarded, or recorded as a lifetime sink), so callers promote the referent. The no-GC `E0310` check likewise covers call-argument sinks, and `lifetime_escaping` summaries now include parameter places (the set was previously never populated).
- **Soundness:** unannotated `let` bindings default numeric inference immediately (integers to `i32`, floats to `f64`). `let x = 300; let y: u8 = x;` previously passed the checker via lingering `InferInt` and generated C that failed to compile; the direct literal form already reported `E0011`.
- **Soundness:** `Trait::method(...)` static calls now verify the `Self` type implements the trait (or that the enclosing bounds prove it for a generic parameter). Without any impl the checker accepted the call and codegen emitted a call through a null function pointer.
- **Soundness:** `*const T as *mut T` casts now require an `unsafe` block, matching the dereference requirement and the Rust rule; widening const to mut previously passed in safe code.
- **Soundness:** the const evaluator uses checked arithmetic and validates the value against the declared constant type, and `as` casts inside constant initializers apply target-type truncation. `const N: usize = 0 - 1;` previously wrapped into `u64::MAX` and became a legal array length. Constant names as array lengths / const-generic arguments now resolve through visibility rules with nearest-preceding-declaration shadowing.
- **Soundness:** bare enum variants (`Option::None`) produce fresh inference variables instead of `Unknown`, so `let x = Option::None; let y: Option<i32> = x;` unifies instead of reporting a misleading `E0001`.
- `SliceIter::next_back` maintains a real back cursor (`SliceIter` carries `index`/`back`, and `next` stops at `back`): it previously returned the final element without consuming anything, so a backward-walk loop ran forever on the last value and mixing ends repeated elements. `tests/mir/std_behavior` pins forward, backward, interleaved, empty, and single-element walks.
- Float `Hash` hashes the value's bit pattern through a `fmix64` (MurmurHash3 finalizer) mix instead of casting to `usize`: the cast truncated, so every fraction below 1.0 (`0.1` … `0.9`, NaN) collapsed onto the same hash. `f32_bits` / `f64_bits` read those bits through a `&[u8]` view instead of dereferencing the value's address as `*const u32` / `*const u64` — an integer read of a `float` object is strict-aliasing UB, which `-O2` may fold away, while unsigned-character access is always defined. Hash values are unchanged (verified against an independent `fmix64` on both backends) and now pinned by exact constants, along with the documented `0.0` / `-0.0` split: they compare equal yet hash apart, which is safe only because floats are `PartialEq` but not `Eq`.
- Float `Display`/`Debug` render `NaN` as `NaN`, infinities as `inf` / `-inf`, keep negative zero's sign (`-0.000000`), and print the exact decimal expansion of any finite value at or above 2^64 (those floats are exact integers; the fraction is `.000000`): `NaN` previously printed `0.000000`, `1.0/0.0` printed `18446744073709551615.000000`, and values beyond `u64` mangled their integer digits (`//////`).
- The C backend emits float constants in scientific notation: Rust's `Display` renders `f64::MAX` as a 309-digit plain integer, and an unsuffixed C integer constant that exceeds `long long` is undefined behavior, so the emitted `((double)179769…0)` truncated before the cast ever widened it (non-finite constants now emit `NAN` / `±INFINITY` from `<math.h>`).
- `std::io::read_line` and `BufReader::read_line` decode the whole line as UTF-8 before replacing the buffer (validating like `fs::read_to_string`): they used to push each byte as a Latin-1 `char`, so multi-byte input became mojibake and never validated. Invalid sequences return the new `ReadError::InvalidUtf8` and leave the buffer empty. `tests/mir/std_behavior` now pipes stdin bytes into the compiled binary to cover multi-byte lines, invalid-sequence rejection, and `BufReader` file lines.
- `parse_with_radix` performs per-digit overflow checks and accepts `i64::MIN`: `"18446744073709551617"` wrapped silently into a small positive value, and `-9223372036854775808` was rejected while `parse_i64` accepted it.
- `str::split("")` no longer loops forever: an empty separator matches between every UTF-8 character boundary, matching Rust semantics. The previous scan never advanced and pushed empty strings until memory was exhausted.
- `fs::read_to_string` validates UTF-8 and returns the new `FsError::InvalidData` instead of reinterpreting arbitrary file bytes as `str`.
- `riddlec --backend c` with multiple files now reports macro-expansion errors and aborts: an unexpanded macro call lowered to `Expr::Missing`, silently dropping the call and every not-yet-expanded macro after it from the generated program (any `println!("{} {}", [a, b])` with a comma-bearing bracket group reproduced this).
- The Pratt parser stops scanning when `type_arg_list_followed_by` lookahead encounters tokens that cannot appear in a type list. Previously `while a < b.len() { ... c > (d) }` paired the condition `<` with a body `(`-followed `>` and misparsed the condition as a generic call.
- `riddlec` and `riddle fmt` survive arbitrarily deep nesting: the recursive-descent parser rejects inputs beyond a nesting depth with a dedicated diagnostic instead of hard-crashing the process (and, for the language server, its analysis thread), and both CLIs run their whole pipeline on a large stack.
- Generic function/method monomorphization suffixes length-encode user type names (`3:A_B_1:C` vs `1:A_3:B_C`), so `<A_B, C>` and `<A, B_C>` can no longer collide into one shared instance with mismatched layout.
- `riddlec` reports `E0401: no main function found in the entry package` for backend builds without `main`, instead of failing later with a linker `WinMain` error. Multi-file invocations also check as one merged package without a backend, matching `--backend c` semantics.
- Windows `fs::read_dir` uses the wide API and converts names to UTF-8: `FindFirstFileA` returned names in the legacy ANSI code page, so non-ASCII file names became empty strings. The no-GC build now frees failed-name buffers. GC out-of-memory exits print a diagnostic, and the aarch64 conservative-stack scan zero-initializes its register snapshot.
- String equality emits a NULL-guarded `memcmp`: a zero-length `String` can carry a NULL pointer, and C11 requires valid `memcmp` pointers even for `n == 0`.
- `unsafe extern "C"` functions returning `char*` copy the returned string into managed memory before wrapping: the C pointer was previously never freed and dangled once the C side freed or reused it.
- Tuple values containing arrays generate zero-init plus `memcpy` element stores like struct values do; brace-initializing an array member from an array expression is a C constraint violation that rejected valid programs at `cc` time.
- `clue build` invokes the C compiler from a common parent with relative paths when any tool-facing path contains non-ASCII characters: the MSYS2 gcc linker fails on absolute paths containing non-ASCII characters, so projects under Chinese directory names could not build at all, even with `CC` set explicitly.
- `clue build` / `clue check` report an error when every binary target's required-features are unsatisfied; the implicit single-target selection previously filtered to an empty list and exited 0 without building anything.
- `Clue.lock` records the default feature set instead of the CLI-requested one, so `clue build --locked --features x` (and `--all-features` / `--no-default-features`) no longer reports the lock as out of date, and its per-package source hash covers only source files and `Clue.toml` rather than every file in the package directory.
- The language server recovers from invalid `textDocument/didChange` batches: a change with an out-of-bounds position previously discarded the whole batch while keeping the desynchronized text, so the document drifted from the editor permanently. The stale document is now dropped, its diagnostics cleared, and a later full-text change re-registers it.
- The `match` guard restriction `E0307` covers field-level moves and moves of the scrutinee itself, not only whole pattern-binding names; the next arm could previously read a value the guard had already moved. `match *r { Item { payload, .. } => payload }` is likewise rejected with `E0308`, matching the `let`-destructure form.
- Moving a borrow into a call keeps it live for the call duration: `take2(r, &value)` where `r: &mut value` was accepted while the inline form `take2(&mut value, &value)` was rejected. Assigning a delayed binding a borrow inside a nested block now clamps the loan to the binding's declaration scope, and `if`/`else` branch origins are unioned.
- `impl Trait` method overrides of generic trait methods no longer trigger a false-positive `E0034`; the trait method generics are resolved symbolically on both sides, generic arity mismatches are their own `E0028`, and overriding a default-method signature is actually checked instead of skipped.

- Lambdas inside generic functions no longer collide across monomorphized instances: the capture-environment struct and lambda symbol name now include the instance's substitution suffix, so `make::<i32>()` and `make::<bool>()` each lower their own lambda function and environment layout instead of sharing one `__riddle_lambda_N` symbol with mismatched capture types (previously a silent C-level pointer-type mismatch whenever a generic function with a capture-containing lambda was instantiated with more than one type). The instance-keyed cache reuses the former generic-lambda table; with `fun<T>` lambdas gone, non-generic lambdas in monomorphized code are its only users.
- Parser error recovery now syncs to context boundaries instead of cascading: a malformed `let` pattern skips to the statement boundary, a missing parameter type keeps the `,`/`)` delimiters intact, a missing struct-field comma reports once and parses the next field, a malformed match-arm body skips to the next arm, and `expect`/missing-`;` errors no longer consume statement-start keywords. Each of these previously emitted three to five diagnostics for one mistake; `tests/frontend` pins the single-diagnostic behavior.
- The `?` operator's `Result`/`Option` recognition falls back to name-based matching when the lang items were never registered (no-std files), mirroring the MIR lowering's fallback; without it, `use_std: false` programs defining their own `Result` were rejected with `E0061` even though the enums were structurally correct. With std loaded the registered lang enums still decide, so a user enum named `Result` cannot hijack `?`.
- - Method call argument inference now solves the receiver's impl-level generics: a parameter written through a distinct generic type (`fun or_insert(self, table: &mut Table<K, V>, ...) -> &mut V`) unifies `Table<K, V>` with the argument instead of leaving the expected type at `Table<_, _>` and reporting `E0001`. This is what unblocks the `HashMap::entry` API above.

Recovery now guarantees forward progress, reports the nesting diagnostic once per parse, and skips the remaining input rather than emitting one cascade error per delimiter. Pinned by `deeply_nested_blocks_report_one_nesting_diagnostic`.
- A move error in a function's tail expression was reported twice: the root block's tail is visited by both the body walk and the block walk, and both reached the same diagnostic, so `fun take<T>(value: &T) -> T { *value }` printed one identical `E0308` (same code, message, and span) twice, and the language server drew two identical squiggles. Pinned by `unbound_parameter_still_cannot_move_out_of_reference`.
- `clue` reported git failures as a bare exit code (`git command failed with exit code: 128`), which hid git's own explanation — an unreachable remote, a missing revision, and an unusable local transport looked identical. Both git helpers now include the captured stderr, and `git_lock_keeps_revision_until_update` skips with an explicit message when the environment cannot run git's local transport instead of failing; `git_dependency_failure_reports_git_output` pins the message.

### Changed

- **The default GC marks payloads by compiler-published layout instead of scanning every payload word by word.** `rgc_alloc` now takes a second argument, a flat `const uint32_t *` descriptor: `descriptor[0]` is the number of GC pointer slots and `descriptor[1 + i]` is the byte offset of slot i inside the payload.
